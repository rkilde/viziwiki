{%- comment -%} CONFIG visual (Level B) — the storage/configuration chart. One row per config: capacity · a fill bar whose width is DERIVED from the capacity (normalized to a common base so GB and TB stay proportional) · price (supports an "old → new" drop) · dates · device-color dots. ORDER is canon, not data order: bars render LOWEST capacity → HIGHEST (lowest at the top). A `revised` config is a "special" — it drops BELOW a hairline divider, and the revised group is itself sorted low→high. So both the live site and the builder read the same ordering from this one file (the builder's reposition animation just re-derives positions from this sort). The sort key is the capacity normalized to GB (1 TB = 1000 GB) zero-padded, paired with the item's ORIGINAL index (so the editor can still bind each row to its data). No modal. Static — all math in Liquid, no JS. Item fields: capacity (number), unit?
